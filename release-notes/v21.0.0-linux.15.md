## Native region overlay (all monitors, ShareX toolbar everywhere)

Region capture no longer depends on an X11 window being placed by each compositor. On Hyprland, sway, niri and KDE Plasma it now runs as native layer-shell surfaces, one per monitor, with the same ShareX toolbar, magnifier, window snapping and annotation tools:

- One selection can span every monitor, including monitors with different scales.
- Drawing is native and fast (about 1 ms per mouse event in benchmarks, down from 75-190 ms), so dragging and annotating no longer lag on big or multi-monitor desktops.
- Safety: Esc always cancels, a stuck overlay is killed and replaced by the window overlay, and the overlay closes by itself after 45 seconds without input. The overlay runs in its own process (`sharex --overlay-helper`).
- `sharex --doctor` shows which overlay is in use. `SHAREX_OVERLAY=window|native` forces one.
- GNOME has no layer-shell and keeps the window overlay for now.

Tested in nested Hyprland (two outputs at 1.0x and 1.6x, automated end to end) and on real Hyprland desktops: a three-monitor desktop with a 1.5x monitor (a selection across a 1.5x and a 1.0x monitor, Esc and right-click cancel) and a 1.25x laptop. KDE, niri and sway need a real-desktop confirmation: please send `sharex --doctor` output if anything looks off.

## `slurp` is gone

`slurp` and `SHAREX_REGION_SELECTOR` are removed everywhere. ShareX's own overlay is the only region selector, so you always get the toolbar and annotation tools.

## KDE

KWin overlay placement now waits for decorations/maximize to settle, raises the overlay above Plasma panels and verifies the result; if placement cannot be verified ShareX logs it and carries on.
