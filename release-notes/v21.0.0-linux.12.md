**niri / sway / Hyprland: ShareX now finds the compositor by itself when it was started without the usual environment variables.**
A ShareX started from systemd, an XDG autostart entry or a display-manager script often has no `NIRI_SOCKET` / `SWAYSOCK` / `HYPRLAND_INSTANCE_SIGNATURE`. All compositor-specific handling was silently skipped then, and on a multi-monitor niri the region overlay showed a window the size of all monitors: only the leftmost monitor was visible, cut off, with a second waybar. ShareX now looks for the running compositor's socket itself.

Also: niri's focused monitor is read from the workspace list (more reliable), and `sharex --doctor` inspects the environment of the *running* ShareX, not only the terminal's, and says what to do if it was started wrongly.

Update: re-run the install one-liner, then restart ShareX (`sharex -ExitShareX`, then use the key).
