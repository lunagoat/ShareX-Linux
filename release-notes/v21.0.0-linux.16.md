## Region capture opens much faster

Print to a visible overlay is now about 0.7 s on a three-monitor desktop, down from about 2.4 s (slower machines gain the same savings and were the ones that felt like 5 s):

- The overlay helper now starts while the screenshot is being taken instead of after it.
- Screenshots are read as raw PPM instead of PNG (about 0.9 s down to 0.25 s for three monitors). The pixels are identical.
- The build is precompiled (ReadyToRun) and the executable is no longer compressed, so every ShareX process starts faster. A cold start shows its first window in about 0.4 s instead of 0.9 s.
- The download grows from about 63 MB to about 98 MB and the installed program from 70 MB to 243 MB, in exchange for the startup time.
- `SHAREX_OVERLAY_TIMING=1` writes a stage-by-stage timeline of the overlay start to the log, for bug reports about slow starts.

## Updating no longer leaves ShareX looking dead

If ShareX was running while you updated it, the old process could no longer read commands from the launcher, so Print and the app icon did nothing until it exited (reported on niri after v21.0.0-linux.15; `Could not load file or assembly System.Text.Encodings.Web` in the log).

- The installer now stops the running ShareX before replacing it (a polite exit first), and tells you to start it again.
- The launcher stops leftover processes whose executable was replaced, found by their exact executable path, then starts a fresh one. This also covers updates through a package manager.
- If you are stuck on the old behaviour right now, run `pkill -x ShareX` and start `sharex` again once.
